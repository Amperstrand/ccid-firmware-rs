# host-tools

Host-side PC/SC utilities for the CCID firmwares in this repo.

## bolty-console / bolty-ctl / burn_cycle

The M5Stick lab rig runs the bolty firmware (see bolty-rs); its daemon-based
HIL tooling lives in bolty-rs `tools/hil/` — including the FT232
single-open console daemon that eliminates the USB-wedge failure class
(bolty-rs docs/lessons-learned.md B11). Use that path when the stick is in
its bolty role.

## boltwipe.py

NTAG424 DNA card verify/wipe driver over PC/SC for the esp32-ccid reader
role of this firmware (any PC/SC reader works). Byte-exact port of the
bolt-card-programmer app's secure messaging, hardware-proven 2026-08-25
(full wipe of a live card, including recovery from an interrupted wipe).

Requires: `pycryptodome`, `pyscard`.

```bash
# offline correctness check (synthetic reference vectors — run this first)
python3 host-tools/boltwipe.py selftest

# read-only key proof: decrypt p= under K1, CMAC-verify c= under K2,
# zero card authentication attempts
python3 host-tools/boltwipe.py verify --uid 04XXXXXXXXXXXX --k1 <hex> --k2 <hex>

# full wipe (auth K0 -> reset file settings -> K1..K4 -> zeros -> K0 last ->
# clear NDEF + tail); --resume-from N continues an interrupted wipe
python3 host-tools/boltwipe.py wipe --uid 04XXXXXXXXXXXX --keys k0,k1,k2,k3,k4
```

The reference vectors in `selftest` are generated by
`bolt-card-programmer/refchangekey.js` (Amperstrand fork) from the phone
app's own crypto — the method that pins this port byte-for-byte (bolty-rs
docs/lessons-learned.md B8). Regenerate both together if the app's
implementation changes.

Card-safety: the driver never guesses keys. A ChangeKey rejection proves
the staged old key is wrong — stop and re-source keys rather than retry
variants (lockout counters count failed *authentications*, which succeed
here or abort; see bolty-rs lessons B6/B7).
